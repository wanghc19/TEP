# Full value card (text for people)

Use only in full-card mode. Write in the user's language, names only (no
codes), every number with its source file. Fill only what bears on the
decision; omit a section that does not apply and say so in one line. Save
as `value-card-<topic>.md` in the repository's scratch directory.

```markdown
# 价值表：<名称>（<日期>）

## 最终目标
| 要求 | 内容 | 出处（用户原话 / 批准记录 / 当前阶段配置） |
|---|---|---|
| 精度 | | |
| 保证形式 | | |
| 适用范围 | | |
| 成本 | | |
（未指定的写"未指定，暂用……"；只有会改变决定时才问用户）

## 本项作用
- 依赖链：最终目标 → … → 本项（每环一句：它解锁什么）
- 必需性：必需（总目标） / 只对当前方法必需 / 不必需；查过哪些替代路线
- 若只对当前方法必需：不需要本项的路线是什么，当前方法比它好在哪里

## 最近对照与查新
已有调研、补查记录（如有）、最接近的工作及差别。

## 预期收益
| 主张 | 类别 | 数字（来源） | 和谁比 | 控制变量是否一致 | 方法自身的差异 | 证据 | 文献里是否已有 |
|---|---|---|---|---|---|---|---|
成本：比较路线时，按使用场景定边界，报告边界内全部成本；边界外的准备只有双方以同样方式使用时才可留在外面，并列出其成本。决定是否追加一步时报增量成本，共同工作单列。缺项要写明。

## 结论有多强（涉及保证时）
结论是什么 / 所需的量能否算出 / 证明状态 / 舍入误差

## 前提条件
| 条件 | 类型 | 典型实例是否满足 | 能否检查及目前状态 | 不成立时的后果 |
|---|---|---|---|---|

## 最小检查
| 检查 | 预算 | 预测 | 结果如何影响决定 |
|---|---|---|---|

## 建议
继续 / 先做最小检查 / 交给用户决定 / 建议停止；理由一到三句。

## 降级方案（只在失败、超预算或目标明显难以实现时）
| 方案 | 放弃了哪项要求 | 还能交付什么 |
|---|---|---|
```
